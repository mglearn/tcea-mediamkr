Privacy

TCEA MediaMkr is designed to protect student and educator privacy.

What we do

  • No accounts. You do not create an account or sign in.
  • No tracking or advertising. There are no analytics scripts or ad trackers.
  • No student data collection. The tools do not ask for student names, emails, or other personal information.
  • Local processing. Your files are opened, edited, and exported in your own browser. The tools are built to avoid uploading your media to a server.
  • Local downloads. When you export, the finished file is saved to your device by your browser.

Fonts

The pages load web fonts (DM Sans, DM Serif Display, DM Mono) from Google Fonts. If your deployment requires zero third-party requests, the fonts can be self-hosted; the layout falls back to system fonts automatically.

Browser permissions

Some tools ask for a browser permission only when you choose a feature that needs it — for example, AudioMkr requests microphone access when you start recording, and screen capture is requested only when you use it. You can decline these and still use the rest of the tool.

Per-tool behavior

Each application documents its actual file, storage, and network behavior in its own folder and in docs/privacy-inventory.md. We do not claim that every operation is fully local unless it has been verified for that specific tool.

Contact

Questions about privacy can be directed to TCEA at <https://tcea.org/>.

Accessibility

TCEA MediaMkr targets WCAG 2.2 AA. Accessibility is treated as a requirement, not an afterthought, across the collection.

Shared commitments

  • Keyboard navigation for interactive controls.
  • Visible focus indicators (:focus-visible) on all focusable elements.
  • Screen-reader labels on controls, menus, and dialogs.
  • Color contrast that meets AA for text and essential UI.
  • Responsive layouts that reflow on small screens and when zoomed.
  • prefers-reduced-motion is honored; non-essential animation is suppressed.
  • A skip link to jump straight to main content.
  • Alternative text for meaningful images; decorative icons are hidden from assistive technology.

Canvas-based editors

Image, video, and drawing tools use a canvas, which is inherently visual. Where a tool relies on a canvas, it provides keyboard-accessible controls and reasonable accessible alternatives (for example, data tables or text summaries for charts in PlotMkr).

Known limits

We do not claim full conformance for every tool until it has been tested with assistive technology. Per-tool accessibility notes are tracked as each application is migrated and verified.

Reporting

If you hit an accessibility barrier, please report it via TCEA at <https://tcea.org/> so it can be prioritized.
